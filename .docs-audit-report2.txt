    18	`CHANGELOG.md` entry (Keep a Changelog format, one factual line + PR link) in

## The two gates

- `npm run check` = typecheck + ESLint (boundaries) + lock-lint (validates
  package-lock.json under npm 10 semantics, exactly what `npm ci` on the
  node-22 CI runner enforces — a local npm 11 `npm install` silently prunes
  optional entries npm 10 requires, which broke CI twice) + dependency-cruiser +
  knip (dead files + dependency hygiene; unused exports/types stay advisory
  during the PRD build-out — see `knip.jsonc`) +
  doc-lint (docs↔config enforcer coverage, injected count tokens, env-schema ⊆
  `.env.example`, dead relative links) + vitest with `--coverage` — the
  **static** gate; coverage thresholds are a ratchet floor (measured minimum
  rounded down, per-metric) enforced here, so a coverage regression fails
  `npm run check`.
- `npm run smoke` = the **runtime** gate: it verifies the installed dependency
  tree matches `package-lock.json`, drops+recreates an isolated
  `agentproofarch_smoke` database (never touches your dev-seeded data), migrates
  and seeds it, boots the real server (`entry.node.ts`) on an ephemeral port and
  drives health → sign-in → todos through the CLI, asserting taxonomy exit codes
  (including unauthorized = exit 3). Assumes `npm run db:up`. Runs in ~5s.

     8	# agentproofarch
     9	
    10	When an AI agent writes most of the code, the thing that decays first is not
    11	correctness — it is *structure*. A generated change lands wherever it compiles,
    12	the seams blur, and six weeks later nobody can say where the boundary between the
    13	database and the domain went. **agentproofarch** is the answer to that specific
    14	failure: a strictly layered full-stack TypeScript foundation where every boundary
    15	is machine-enforced by lint, every capability is drivable from a CLI with `--json`
    16	output and deterministic exit codes, and "done" is defined as two green gates
    17	rather than a green typecheck. The architecture is written down first
    18	(`docs/architecture.md` is normative), the enforcers are written down next, and
    19	`demo/` is a running reference implementation of both.
    20	
    21	A free, open project by **Mateusz Choma**, developed privately in collaboration
    22	with **[CodeRoad.pl](https://coderoad.pl)** and
    23	**[AmazingDesign.eu](https://amazingdesign.eu)**.
    24	
    25	## What it is, precisely
    26	
    27	A pure-TypeScript core — `core/domain` (entities, `Result`, the error taxonomy),
    28	`core/contract` (routes + zod schemas), `core/server` (use-cases + ports),
    29	`core/client` (the typed HTTP client) — surrounded by thin adapters (Drizzle
    30	database, Better Auth, email, domain provisioning) and thin apps (a Hono HTTP
    31	server, a React SPA, a commander CLI). `core/**` may not import hono, react,
    32	drizzle, better-auth, pg or commander; `core/domain` depends on zod alone;
    33	`apps/server/src/composition.ts` is the only place a *server* adapter is
    34	instantiated. None of that is a convention you are asked to remember — it is
    35	`eslint-plugin-boundaries` plus dependency-cruiser, and violating it fails the
    36	build.
    37	
    38	The demo is a **walking skeleton**, not a scaffold: authentication (password,
    39	magic link, TOTP two-factor, passkeys, plus a Google seam that stays dormant
    40	unless both of its env vars are set), foundation-owned tenants with flat
    41	`owner`/`admin` staff grants, tenant resolution by custom domain or subdomain,
    42	end-customer members with GDPR export and removal, todos, two exemplar boards (a
    43	personal one and a WIP-guarded team one), and a public unauthenticated read
    44	surface — each one flowing through *every* layer and reachable from all three
    45	drive surfaces.
    46	
    47	## Who it is for
    48	
    49	| You are… | What you get from this |
    50	|---|---|
    51	| **Building a multi-tenant SaaS with agents doing the typing** | A layout where a generated change either lands inside a seam or turns a gate red — plus a scaffolder that plants a resource and hands you the 12-step wiring checklist. |
    52	| **Evaluating how far layering can actually be enforced** | A concrete answer: `eslint-plugin-boundaries`, dependency-cruiser, custom `agentproofarch/*` rules, a docs↔enforcer cross-check (`doc-lint`), and probes that feed each rule a violating fixture to prove it still bites. |
    53	| **Deciding whether to trust an AI-written codebase** | The verification story, warts included: a fail-closed AI-review gate, post-deploy commit-SHA attestation, a flake-is-a-P1 rule, and a register of work that was accepted and deliberately *not* built. |
    54	| **Planning to self-host** | The same commit runs on Vercel + Neon and on a Docker stack (Node + Postgres + Caddy on-demand TLS), with a CI job that boots the container stack and smokes it. |
    55

    57	`demo/package.json` is `private: true`, nothing is published to npm, and the
    58	project carries no version numbers — a release is a branch promotion
